## Проект
Своя прошивка (лаунчер + приложения) для M5Stack Cardputer ADV (ESP32-S3, 8 МБ flash, без PSRAM, ~320 КБ ОЗУ, клавиатура 4x14) с внешним экраном ILI9341 320x240 (горизонтально). Windows, CLion + PlatformIO (pioarduino), Arduino framework, библиотека M5Cardputer (внутри M5GFX/LovyanGFX). Сборка: `pio run -e cardputer`, прошивка по USB: `pio run -e cardputer -t upload` (G0 зажать при включении). Исходники строго в `src`.

## Структура
- `src/main.cpp` — цикл: клавиша -> `onKey`, затем `update(ms)`, если был `invalidate()` -> `draw()`. Выход из приложения: `requestExit()`.
- `src/app.h` — базовый класс `App`, `AppEntry {title, group, create}`, реестр `kApps`, список групп `kGroups`.
- `src/registry.cpp` — группы и приложения.
- `src/launcher.h` — лаунчер: сначала список групп, внутри группы список приложений. Esc в группе = назад.
- `src/apps/<имя>.h` — одно приложение = один файл: класс-наследник `App` + `inline App* createXxx() { return new Xxx(); }`. Большие приложения можно делить на .h/.cpp в `src/apps/`.
- `src/ui.h` — ЕДИНЫЙ СТИЛЬ: константы и функции оформления (см. ниже).
- `src/theme.h/.cpp` — тема и настройки интерфейса (приложение «Настройки», хранится в NVS).
- `src/display.h` — глобальный экран `gfx` (LGFX), шрифт с кириллицей `UI_FONT`. Рисовать между `gfx.startWrite()` и `gfx.endWrite()`.
- `src/config.h` — `SCREEN_W/SCREEN_H`, цвета-макросы, `RGB565(r,g,b)`.
- `src/input.h` — `KeyEvent {Key key; char ch;}`, `Key: NONE, UP, DOWN, LEFT, RIGHT, ENTER, ESC, DEL, CHAR`.
- `src/storage.h` — SD: `g_sdOk`, `SD.open("/путь")`.

## Базовый класс
```cpp
class App {
public:
  virtual ~App() {}
  virtual void start() {}                  // при входе
  virtual void stop() {}                   // при выходе
  virtual void onKey(const KeyEvent& e) = 0;
  virtual void update(uint32_t nowMs) {}   // каждый цикл (игры, таймеры)
  virtual void draw() = 0;                 // вызывается после invalidate()
  void invalidate();  void requestExit();
};
```

## ЕДИНЫЙ СТИЛЬ (обязательно)
Цвета. Только макросы темы, никаких своих RGB:
- `C_BG` фон, `C_FG` основной текст, `C_DIM` второстепенный текст и подсказки, `C_ACCENT` акцент (заголовки, выделенные элементы, кнопки), `C_SEL` фон выбранной строки, `C_OK` успех, `C_ERR` ошибка.
- Это переменные: тема меняется в «Настройках», поэтому цвета брать при каждой отрисовке, не кэшировать в статических константах. Приложение должно нормально выглядеть на светлой и тёмной темах. Исключение: игровые и графические элементы (спрайты, график, элементы таблицы Менделеева), там свои цвета допустимы, но фон, текст и рамки интерфейса всё равно из темы.

Раскладка экрана 320x240 (константы в `ui::`):
- Сверху заголовок `ui::titleBar("Название")` (высота `ui::TITLE_H`=24, полоса акцентного цвета, белый текст, название коротко, по-русски).
- Список/контент начинается с `ui::LIST_TOP`=28, строка списка `ui::ROW_H`=22 через `ui::row(y, "Название", "значение", выбрана)`. Выбранная строка подсвечена `C_SEL`, значения справа серым `C_DIM`, левый отступ `ui::PAD`=10.
- Внизу на `ui::FOOT_Y`=222 подсказка по клавишам `ui::footer("...")` (коротко, одна строка, на каждом экране).
- Видимых строк списка `ui::visibleRows()`; длинные списки скроллить так, чтобы выбранная строка была видна.
- Один шрифт `UI_FONT`, без смены размеров в интерфейсе. Заголовок, подсказка и строки только через `ui::`-функции. Если нужного элемента нет (диалог, ввод текста, прогресс-бар), предложи добавить его в `ui.h` отдельным файлом и использовать в других приложениях, не копируй код в приложение.
- Сообщения: успех `C_OK`, ошибка `C_ERR`, остальное `C_FG`/`C_DIM`.

Клавиши (одинаково во всех приложениях):
- Fn+; вверх, Fn+. вниз, Fn+, влево, Fn+/ вправо. В списках можно принимать и `;` `.` `,` `/` без Fn.
- Enter = выбрать/подтвердить, Esc (Fn+`) = выход из приложения или назад на один уровень (`requestExit()`), Del = стереть символ.
- Не придумывать свои раскладки; если клавиш не хватает, использовать слои Fn и описать их в подсказке.

Группы и регистрация:
- Каждое приложение принадлежит одной группе из `kGroups` (сейчас: Учёба, Игры, Хакинг, Система; новая группа добавляется строкой в `kGroups`, пустые группы скрыты).
- Регистрация в `registry.cpp`: `#include "apps/имя.h"` и строка `{"Название", "Группа", createИмя},`.
- Свои настройки приложения хранить в NVS (`Preferences`) в пространстве имён `app_<имя>`, пространство `ui` не трогать.

## Жёсткие технические требования
- ОЗУ мало: НЕ делать полноэкранный 16-битный буфер (~150 КБ). Рисовать напрямую в `gfx` или небольшими спрайтами/полосами. Не выделять большие массивы на стеке.
- `draw()` вызывается только после `invalidate()`, перерисовывать только изменившееся. Игры: `invalidate()` из `update()` по таймеру.
- Без блокирующих `delay()` в приложении.
- Кириллица только через `UI_FONT`. Формулы (степени, индексы, дроби, греческие буквы) рисовать вручную.
- Тексты и таблицы хранить файлами на SD (или во flash), а не в коде.
- Не менять чужие файлы, кроме двух строк в `registry.cpp`.

## Шаблон (src/apps/template.h)
```cpp
#pragma once
#include <stdio.h>
#include "../app.h"
#include "../ui.h"

class TemplateApp : public App {
public:
  void start() override { _count = 0; }
  void onKey(const KeyEvent& e) override {
    if (e.key == Key::ESC) { requestExit(); return; }
    if (e.key == Key::ENTER) { _count++; invalidate(); }
  }
  void draw() override {
    gfx.startWrite();
    gfx.fillScreen(C_BG);
    ui::titleBar("Шаблон приложения");
    char buf[40];
    snprintf(buf, sizeof(buf), "Enter нажат: %d", _count);
    gfx.setTextColor(C_FG, C_BG);
    gfx.drawString(buf, ui::PAD, ui::LIST_TOP + 8);
    ui::footer("Enter +1   Fn+` выход");
    gfx.endWrite();
  }
private:
  int _count = 0;
};
inline App* createTemplate() { return new TemplateApp(); }
```
